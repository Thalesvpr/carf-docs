# Movimento

Movimento no CARF e funcional, nunca decorativo. Animacoes existem para confirmar acoes, guiar atencao e suavizar transicoes que seriam bruscas demais. Se uma animacao nao serve a um desses propositos, ela nao deveria existir.

Feedback de acao e instantaneo. Quando o usuario toca um botao, algo muda imediatamente - cor, escala, sombra. Essa resposta confirma que o toque foi registrado antes mesmo do resultado chegar. Em conexoes lentas, esse feedback e crucial para evitar toques repetidos de frustacao.

Transicoes entre estados sao suaves mas rapidas. Uma tela nao pisca para outra - ela transiciona. Um elemento nao aparece do nada - ele entra. Mas essas transicoes sao breves, nunca atrasando o usuario que tem pressa.

## Quando nao animar

Carregamento de dados nao deve ter animacoes elaboradas - um indicador simples basta. Listas longas nao animam cada item individualmente - a lista aparece. Acoes criticas como salvar ou enviar nao tem animacoes que atrasem a confirmacao. O usuario quer saber que funcionou, nao assistir a uma coreografia.

Respeite preferencias de sistema para movimento reduzido. Alguns usuarios tem sensibilidade a animacoes ou usam tecnologias assistivas que se confundem com elementos em movimento.
