# FUNCTIONAL-REQUIREMENTS

Requisitos funcionais do CARF especificando o que o sistema deve fazer sem detalhar como implementar. Cada requisito possui descricao objetiva focada no comportamento esperado, criterios de aceitacao em formato testavel, e rastreabilidade para casos de uso e user stories relacionadas. Servem como fonte unica de verdade para que projetos referenciem estes requisitos ao inves de duplica-los.

Os requisitos estao organizados em 17 dominios: [autenticacao e seguranca](./01-auth-security/README.md) com integracao Keycloak, [gestao de tenants](./02-tenants/README.md) para multi-tenancy, [usuarios e equipes](./03-users-teams/README.md), [notificacoes](./04-notifications/README.md), [comunidades](./05-communities/README.md) e [unidades habitacionais](./06-units/README.md) como entidades centrais do cadastro, [titulares](./07-holders/README.md), [documentos e midia](./08-documents-media/README.md) incluindo ortofotos, [camadas e features](./09-layers-features/README.md) geoespaciais, [analise espacial](./10-spatial-analysis/README.md) com PostGIS, [anotacoes](./11-annotations/README.md), [levantamentos topograficos](./12-surveys/README.md), [processos de legitimacao](./13-legitimation/README.md) conforme Lei 13.465/2017, [modo offline e sincronizacao](./14-offline-sync/README.md) para aplicativo mobile, [exportacao de dados](./15-data-export/README.md), [relatorios](./16-reports/README.md), e [integracoes WMS/WMTS](./17-wms-wmts/README.md) para mapas externos.
