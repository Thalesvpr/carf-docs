# Acessibilidade

WEBDOCS segue WCAG 2.1 nível AA garantindo que documentação é acessível para pessoas com deficiências visuais, auditivas, motoras e cognitivas. Starlight fornece base acessível mas conteúdo deve seguir práticas adicionais.

Imagens requerem texto alternativo descritivo no atributo alt. Descrição deve comunicar informação que imagem transmite, não apenas descrever visualmente. Para screenshots, descrever ação ou resultado mostrado. Imagens decorativas usam alt vazio.

Headings seguem hierarquia lógica sem pular níveis. Página começa com h1 (título), seções principais usam h2, subseções usam h3. Estrutura permite navegação via leitor de tela e melhora SEO. Evitar usar headings apenas para estilização.

Links têm texto descritivo indicando destino. Evitar "clique aqui" ou "saiba mais" sem contexto. Preferir "consulte a documentação de autenticação" que faz sentido lido isoladamente. URLs longas não devem ser texto do link.

Contraste de cores segue ratio mínimo 4.5:1 para texto normal e 3:1 para texto grande. Tema CARF foi validado para ambos modos (claro e escuro). Não usar cor como único indicador de significado.

Tabelas têm headers de coluna marcados com th e scope apropriado. Evitar tabelas complexas com células mescladas. Tabelas de dados devem ter caption ou título descritivo. Considerar listas como alternativa para dados simples.

Vídeos embutidos devem ter legendas ou transcrição disponível. YouTube fornece legendas automáticas mas revisar para garantir precisão. Áudio significativo deve ter alternativa textual.
